# apps/admin: platform admin back-office

Internal tool for the platform owner. Read the root `AGENTS.md` first; this file adds admin-only rules.

## What it is

- Cross-tenant view and actions: tenants, users, subscriptions, failed jobs, platform audit log.
- Talks only to `/api/admin/rpc` through `@starter/contracts/admin`.
- Access: allowlisted emails (`PLATFORM_ADMINS`) + admin host check (+ optional Cloudflare Access). Non-admins see "Not authorized".

## UI: shadcn/ui

- Components live in `src/components/ui` (generated by the shadcn CLI, owned and committed). Add with:
  `pnpm --filter @starter/admin exec shadcn add <component>`
- Use shadcn's default neutral look, light/dark by system preference. No theme switcher.
- Customize by editing the generated source. Do not create wrapper abstractions around shadcn components.
- Data tables: shadcn data-table pattern on TanStack Table. Filters, sort and pagination in typed search params (`validateSearch`), never component state.
- Forms: TanStack Form + shadcn `Field`. No react-hook-form.
- Feedback: `sonner` toasts for results; `alert-dialog` for every mutation.
- Never import `@starter/ui` here. Never copy files from here into `packages/ui`.

## Rules

1. Every mutation: confirmation `alert-dialog` showing the target (tenant name / user email) + required reason field (min 5 chars), sent to the API as `reason`.
2. No business logic in the frontend. Rules (trial length, status transitions, entitlements) live in `apps/api/src/core`.
3. English only; no i18n messages.
4. Show IDs in a monospace, copyable form on detail pages (support work needs them).
5. Out of scope: impersonation, deleting tenants, editing tenant business data, metrics dashboards, bulk actions.

## API side (apps/api/src/admin)

- Every procedure goes through the `platformAdmin` middleware.
- Reads use `withSystem`; writes call functions in `apps/api/src/core/*` inside one transaction together with the `platform_audit_events` row.
- Tests live next to the services and cover: non-admin → NOT_FOUND, audit row per mutation, reason validation.
